## Decisions
- `url` frontmatter field always holds the real, case-preserved hostname/domain (not the simplified note title) since it needs to be a working link.
- When a host exposes multiple services, only the primary one goes in `url`; others go in Configuration notes as `Label: address` lines.
- Network devices that route/switch for the entire network get `vlan` set to the full explicit VLAN list, not a single VLAN or the word "All".
- Went through a multi-plugin trial-and-error trying to match a YouTuber's homelab-vault workflow (clickable `type` field, folder-click table, colored labels): Metadata Menu (hit and fixed a real `classFilesPath` plugin bug, then abandoned), native Bases (`Hosts.base`, kept), Folder Notes (kept — confirmed this is what makes clicking the `Hosts` folder open the table), Tags property type (reverted — polluted autosuggest with unrelated vault tags), Colored Tags Wrangler (removed — only colors the real `tags:` property, not custom ones). Landed on: Bases + Folder Notes for the table/folder-click behavior; `type` stayed a plain Text property with no color styling. Root-caused the coloring/icons the YouTuber used to likely be the **Pretty Properties** plugin (not installed — no action taken).
- Fully removed Metadata Menu (plugin + `fileClasses/Host.md` + `fileClass: Host` frontmatter across all host notes and the template) once Bases proved sufficient.
- Dave moved `02. Private/Resources/Networking` → `02. Private/Resources/Homelab/Networking`; fixed `Hosts.base`'s hardcoded folder-filter path and a stale path reference in `CLAUDE.md`. Full detail in [[03-07-2026-homelab-ipam]].
